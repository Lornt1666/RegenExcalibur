# Finite Completion Protocol

When a project-oriented prompt requests definitive completion, the compiled runtime must require:

1. Final concept.
2. Full applicable specification.
3. Differentiated innovation with an honest novelty class.
4. Implementation blueprint.
5. Definitive completion record.

The completion record names the requested target, achieved state, requirements status, innovation status, superiority status, evidence, residual limitations, out-of-scope work, blockers, and exactly one truthful terminal declaration.

The runtime must stop after the defined output contract passes. It must not invent another phase simply because further improvements can be imagined.
